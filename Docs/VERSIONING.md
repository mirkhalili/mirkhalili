# کاربرد طرح QAVNS در پروژهٔ سایت میر خلیلی

سند بالادستی و معتبر: [QAVNS.md](QAVNS.md) — «طرح چهارگانه تطابق‌پذیر شماره‌گذاری نگارش‌ها»
(Quadruple Adaptive Version Numbering Scheme). این سند فقط **نحوهٔ تطبیق** آن طرح بر این پروژه را ثبت می‌کند.

## ۱) شناسهٔ نگارش در این پروژه

```
e0RSN.G.FF.CCC[-PRI][-BMD]
```

| فیلد | نام (طبق QAVNS) | قاعدهٔ 채택‌شده در این پروژه |
|---|---|---|
| `e0RSN` | شماره ترتیب نشر | سه رقم با پیش‌صفر؛ **هر نشر (Release) یک واحد** زیاد می‌شود؛ اگر روزی از ۹۹ گذشت، پیشوند `e` (پیش‌صفری توسعه‌یافته) اضافه می‌شود |
| `G` | شماره نسل | با تغییر بنیادی (دگرگونی معماری/پشته یا بازطراحی کامل رابط) یک واحد زیاد و `FF`/`CCC` صفر می‌شوند |
| `FF` | شماره لیست قابلیت‌ها | با افزودن/تغییر قابلیت یا محتوای غیربنیادی یک واحد زیاد می‌شود |
| `CCC` | شماره لیست تصحیحات | نشرِ فقط-تصحیح: یک واحد زیاد؛ نشرِ فقط-قابلیت: بازنشانی به `0`؛ نشرِ ترکیبی: بازنشانی به `1` |
| `PRI` | پیش‌انتشار | فعلاً استفاده نمی‌شود (در آینده برای نسخه‌های آزمایشی: `b1`, `rc1` و…) |
| `BMD` | ابردادهٔ ساخت | فعلاً استفاده نمی‌شود |

«شئ اطلاعاتی» در این پروژه = **کل وب‌سایت CMS** (کد PHP + مستندات + دارایی‌ها). از نگارش 005.2.2.0 به بعد، نسخهٔ استاتیک Astro حذف شد و شئ فقط CMS را شامل می‌شود.

## ۲) تاریخچهٔ نگارش‌ها

| شناسهٔ نگارش | نوع دلتا نسبت به قبل | خلاصهٔ نشر |
|---|---|---|

| **003.2.0.0** | بنیادی (G+1 → FF/CCC صفر) | نگارش کلان دوم: نسخهٔ CMS با PHP + MySQL، پنل ادمین، `schema.sql`، `install.php` |
| **004.2.1.0** | فقط-قابلیت (FF+1، CCC=0) | پوشهٔ `Docs/` (۱۰ سند)، انتقال سند QAVNS به `Docs/`، انتشار رسمی روی `main`، بستهٔ فشردهٔ انتشار |
| **005.2.2.0** | فقط-قابلیت (FF+1، CCC=0) | **نگارش جاری** — حذف `install.php` و نسخهٔ استاتیک، تثبیت ریشه به‌عنوان `public_html`، `config.sample.php` فارسی، مستندات به‌روز با نصب بدون install.php |

## ۳) آیین ساخت نگارش جدید (الزام‌آور)

1. تغییرات روی شاخهٔ کاری؛ مستندسازی هر قابلیت/تغییر در `Docs/` و به‌روزرسانی نگاشت `Docs/README.md`
2. تعیین شناسهٔ جدید طبق قواعد بخش ۱ و ثبت دلتا در `CHANGELOG.md` + به‌روزرسانی `VERSION`
3. commit → push → **Pull Request به `main`** → merge (فایل‌های نهایی فقط از این مسیر وارد `main` می‌شوند)
4. تگ `v<شناسه>` و ساخت GitHub Release با بستهٔ فشردهٔ `mirkhalili-<شناسه>.zip` از درخت `main`
5. **ارائهٔ لینک دانلود بستهٔ فشرده به کارفرما در پایان هر تغییر**
6. پس از نشر، محتوای آن نگارش هرگز تغییر نمی‌کند؛ هر تغییری در نگارش بعدی اعمال می‌شود

## ۴) مرتب‌سازی لغوی

به لطف پیش‌صفری سه‌رقمی `e0RSN`، نام بسته‌ها و تگ‌ها به‌درستی مرتب می‌شوند
(`mirkhalili-005.2.2.0.zip` پس از `mirkhalili-004.2.1.0.zip`)؛ در صورت سرریز سه رقم،
شگرد پیش‌صفری توسعه‌یافته (`e1000.…`) به‌کار می‌رود.

## ۵) نگارش جاری

`005.2.2.0` — مقدار فایل `VERSION` ریشه نیز همین شناسه است.
